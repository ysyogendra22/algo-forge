#datastructure
#### 1. What is a Data Structure?

1. A **Data Structure** is a way of organizing and storing data so it can be accessed and modified efficiently.
2. Different data structures are optimized for different operations.
3. Choosing the right data structure directly affects performance and code complexity.

#### 2. Why Do We Need Data Structures?

1. Store and organize data.
2. Search data efficiently.
3. Insert and delete data efficiently.
4. Process large amounts of data.
5. Represent relationships between data.
6. Optimize time and memory usage.

#### 3. Basic Operations

1. **Access** — Get an element.
2. **Search** — Find an element.
3. **Insert** — Add an element.
4. **Delete** — Remove an element.
5. **Update** — Modify an element.
6. **Traverse** — Visit elements.

#### 4. Main Categories

1. **Linear Data Structures** — Elements are arranged sequentially.
   - Array
   - Linked List
   - Stack
   - Queue

2. **Non-Linear Data Structures** — Elements form hierarchical or network relationships.
   - Tree
   - Graph
   - Trie

3. **Hash-Based Data Structures** — Use hashing for fast lookup.
   - HashMap
   - HashSet

#### 5. Core Data Structures to Know

1. **Array** — Fast indexed access.
2. **Linked List** — Node-based sequential structure.
3. **Stack** — LIFO.
4. **Queue** — FIFO.
5. **HashMap** — Key-value lookup.
6. **HashSet** — Unique values with fast lookup.
7. **Tree** — Hierarchical data.
8. **Heap** — Priority-based access.
9. **Trie** — Prefix-based searching.
10. **Graph** — Represents relationships/networks.

#### 6. Complexity — Must Know

Understand the cost of operations using **Big-O**.

1. `O(1)` — Constant.
2. `O(log n)` — Logarithmic.
3. `O(n)` — Linear.
4. `O(n log n)` — Common efficient sorting complexity.
5. `O(n²)` — Quadratic.

Always think about:

- Time Complexity
- Space Complexity

#### 7. How to Choose a Data Structure

Ask what operation matters most:

1. Need fast indexed access? → **Array**
2. Need LIFO processing? → **Stack**
3. Need FIFO processing? → **Queue**
4. Need fast key lookup? → **HashMap**
5. Need unique values? → **HashSet**
6. Need hierarchical relationships? → **Tree**
7. Need priority processing? → **Heap**
8. Need prefix search? → **Trie**
9. Need network/relationship modeling? → **Graph**

#### 8. Interview Must Remember

1. There is no universally "best" data structure.
2. Selection depends on required operations and constraints.
3. Know the common operations and their complexity.
4. Understand the trade-off between time and space.
5. Learn data structures together with their common problem-solving patterns.
6. In interviews, choosing the right data structure is often more important than writing code immediately.
